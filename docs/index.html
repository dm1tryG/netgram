The opposite bet

Least-privilege by default

Most Telegram MCP servers log in as a userbot and hand the AI full access to everything — all your DMs, groups and channels, with send rights. NetGram flips it.

Permission model

One dial per chat

An escalating level you set yourself in the web UI — full ⊃ write ⊃ read. Enforced server-side: a request outside the allowlist never reaches Telegram.

off

Nothing. The server rejects every read and write for this chat.

read

The AI can read that chat's messages — including inline buttons.

write

The AI can propose messages and clicks. Each one waits as a draft until you approve it in /drafts.

full

Your explicit opt-in to autonomy — proposals execute immediately, no approval. Grant only if you mean it.

Model Context Protocol

Drive it from your AI

Ships an MCP server so any client — Claude Desktop, Claude Code, Cursor, Cline — can use it. The tools are deliberately read + propose only.

list_chatslist dialogs with access level + kind; filter by kind/title
read_messagesrecent messages of a read-allowed chat (incl. inline buttons)
propose_messagequeue a text message as a draft (needs write)
propose_button_clickqueue an inline-button click as a draft (needs write)
list_draftslist pending / sent drafts
Absent by design: there is no tool to grant permissions or to approve/send a draft. Those are human-only, in the web UI. The worst an AI can do is read chats you allowed and pile up drafts you can ignore.

How it works

A thin, safe bridge

GramJS logs in with your account over MTProto. The allowlist gate and draft approval sit between the AI and Telegram.

AI (MCP client)  ──stdio──▶  mcp/server.mjs  ──HTTP──▶  NetGram (Next.js)
                                                       │  allowlist gate (per chat)
you (browser)  ─────────────────────────────────────▶ │  drafts + approval
                                                       └─ GramJS / MTProto ─▶ Telegram
🔒

Server-side gate

The allowlist is enforced in the API, not the client — the agent physically can't reach a chat you didn't allow.

✍️

Human-in-the-loop

Anything that leaves your account is a draft. The confirm dialog even defaults to Cancel.

🏠

Local-first state

Creds, session, allowlist and drafts live in ./data — git-ignored, nothing shared with a third party.

Quick start

Running in one command

Docker, your own api_id / api_hash from my.telegram.org, and a setup screen — nothing to edit in files.

bash
$ git clone https://github.com/dm1tryG/netgram.git
$ cd netgram
$ docker compose up -d --build

# then open http://localhost:3000
# 1. paste your api_id / api_hash + phone, enter the login code
# 2. open /permissions and switch on the chats the AI may touch

Read your chats. Propose actions.
You press send.
